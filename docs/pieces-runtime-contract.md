# Activepieces-on-Temporal runtime contract

Single orchestrator (Temporal `DynamicWorkflow` in `apps/reasoner`). Activepieces pieces
execute as a Temporal **activity** implemented by a dedicated Node activity worker
(`apps/pieces-worker`) that loads piece npm packages as a library and invokes the real
`action.run(context)`. No Activepieces orchestrator/flow-worker is used. The vendored
tree under `external/activepieces` stays reference-only.

Everything below is a hard contract between the three components. Do not deviate;
if something is impossible as specified, stop and report instead of improvising.

## 1. Node type convention

Piece-backed node types are namespaced with the `pieces.` prefix:

```
pieces.<piece-slug>.<action-name>
```

- `<piece-slug>` = npm package name minus the `@activepieces/piece-` prefix
  (e.g. `@activepieces/piece-google-sheets` → `google-sheets`).
- `<action-name>` = the action's `name` as declared in `createAction` (snake_case,
  verbatim — do not camelize).
- Example: `pieces.slack.send_channel_message`.

The `pieces.` prefix is load-bearing: the Python workflow routes on
`type.startswith("pieces.")` deterministically, with no file I/O in workflow code.
Existing catalog types (`notion.createPage`, `gsheets.appendRow`, …) are unaffected;
resolution order stays: built-in registry → catalog → **pieces index** → passthrough.

## 2. Piece index — `packages/nodes/pieces/index.json`

Generated by `apps/pieces-worker` (`npm run gen:index`) by importing every installed
`@activepieces/piece-*` package. Consumed by the Go planner/catalog and (for metadata
only, never in workflow code) by the Python reasoner.

```json
{
  "version": 1,
  "generatedAt": "2026-07-16T00:00:00Z",
  "nodes": [
    {
      "id": "pieces.slack.send_channel_message",
      "piece": "@activepieces/piece-slack",
      "pieceVersion": "0.11.4",
      "action": "send_channel_message",
      "label": "Send message to a channel",
      "description": "…",
      "kind": "action",
      "search": ["slack", "message", "chat"],
      "auth": { "type": "oauth2", "credentialKey": "AP_SLACK_AUTH", "required": true },
      "props": [
        { "key": "channel", "label": "Channel", "type": "short_text",
          "required": true, "description": "…" }
      ]
    }
  ]
}
```

- `auth.type` ∈ `oauth2 | secret_text | basic_auth | custom_auth | none`
  (the framework's PropertyType, lower-cased).
- `props[].type` is the framework's property type name lower-cased
  (`short_text`, `long_text`, `number`, `checkbox`, `static_dropdown`, `json`, `array`,
  `object`, `dropdown`, `dynamic`, …). Dynamic/dropdown props are included in the index
  (planner may still set them as plain values) but marked `"dynamic": true`.
- Only `kind: "action"` nodes for now. Triggers are out of scope for this phase.

## 3. Temporal topology

- Task queue: **`agently-pieces`** (env override `PIECES_TASK_QUEUE`, both sides).
- Activity name: **`execute_piece`** (registered by the Node worker; invoked by name
  from the Python workflow with `task_queue=<pieces queue>`).
- Temporal connection env (shared with reasoner, verified against
  `apps/reasoner/reasoner/config.py:80-82`): `TEMPORAL_HOSTPORT`
  (default `localhost:7233`), `TEMPORAL_NAMESPACE` (default `default`).
  The reasoner's own queue is `TEMPORAL_TASK_QUEUE` (default `agently-reasoner`) —
  the pieces worker must NOT poll that queue.
- Workflow-side timeouts for `execute_piece`: `schedule_to_start_timeout=30s`,
  `start_to_close_timeout=180s`, retry policy `maximum_attempts=3`.

## 4. `execute_piece` payload contract

Single JSON argument:

```json
{
  "piece": "@activepieces/piece-slack",
  "pieceVersion": "0.11.4",
  "action": "send_channel_message",
  "props": { "channel": "#general", "text": "hi" },
  "authEnvKey": "AP_SLACK_AUTH"
}
```

- `props` arrive **fully rendered** — the Python side resolves all `{{…}}` templates
  against `config`/`input`/`outputs` before scheduling. The Node worker never templates.
- `authEnvKey` is the credential env var NAME (`null` for auth-less pieces). The
  secret itself never crosses the Temporal payload boundary (payloads persist in
  workflow event history). The **Node worker** resolves `process.env[authEnvKey]`
  and normalizes it to the shape the piece's auth property expects: value parsed as
  JSON if it parses, else raw string; oauth2 + bare string →
  `{ access_token: "<string>" }`; basic/custom → object passthrough. A missing env
  var on the worker → `{ "ok": false, "errorType": "MissingCredential" }` (returned,
  not thrown), which the reasoner records as intent.

Single JSON result — piece-level failures are **returned, not thrown** (so Temporal
does not retry business errors); only infra failures (piece not installed, worker bug)
throw and use the retry policy:

```json
{ "ok": true,  "output": { …piece run() return value, JSON-safe… } }
{ "ok": false, "error": "human-readable message", "errorType": "PieceExecutionError" }
```

## 5. Credentials

Env var per piece: **`AP_<SLUG_UPPER>_AUTH`** where `SLUG_UPPER` is the piece slug
upper-cased with `-` → `_` (e.g. `AP_GOOGLE_SHEETS_AUTH`). Both workers load the
shared repo-root `.env`. The **Python** side only checks *presence* (inside an
activity, never in workflow code) so an unconfigured piece degrades to
record-intent without a cross-queue round-trip; the **Node** side reads the value.
Missing/empty credential for a piece whose `auth.required` is true → do not
schedule `execute_piece`; degrade to the existing record-intent shape:

```json
{ "recorded": true, "executed": false, "missingCredentials": ["AP_SLACK_AUTH"] }
```

The same degradation applies when `execute_piece` fails its schedule_to_start timeout
(no pieces worker polling): record intent with `"reason": "pieces-worker-unavailable"`,
never fail the run.

## 6. Component boundaries (who writes what)

- `apps/pieces-worker/**` and `packages/nodes/pieces/**` — Node worker + index (task 1).
- `apps/reasoner/**` — routing, rendering, credential resolution, persistence (task 2).
- `apps/api/internal/services/**` — planner/catalog awareness of the index (task 3).
