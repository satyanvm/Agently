# v1-13 — Semantic piece routing: route → map → reduce

Branch `v1-13`, PR [#24](https://github.com/satyanvm/Agently/pull/24), commit `79db810b`.
This document records everything done in this session: the problem analysis, the
architecture that replaced the old one, every implementation detail, the evidence
gathered, and a reading guide for the whole project.

---

## 1. The problem

Prompt→workflow compilation (`apps/api/internal/services/planner.go`) is a
**map-reduce compiler** over the node catalog: a small fast model selects
plausible nodes per cluster (map), then the strongest model authors the full
typed DAG from only the selected schemas (reduce), followed by a
validate→repair loop and a deterministic fallback.

That shape is sound. The weak link was **how piece clusters were selected**.
The catalog has two very different populations:

| population | clusters | nodes | map treatment (before v1-13) |
|---|---|---|---|
| hand-written integrations | ~12 | ~193 | one LLM map call per cluster |
| Activepieces pieces (`pieces.<slug>`) | **707** | **6,758** | lexical prescreen → top 12 get map calls |

707 clusters is too many for one LLM call each — so the old code prescreened
them with `topPieceClusters`: a token-overlap score (slug word hit = +3, any
distinct prompt token found in a node's `search`/`label` = +1), top 12 survive.

### Why that was broken

1. **Zero semantic recall.** Pure string matching: "add a row to my
   spreadsheet" shares no token with `google-sheets`; "text me" never finds
   `twilio`; "update the CRM" never finds `hubspot`. If the user doesn't name
   the service with the same words the piece uses, the piece scores 0 and is
   invisible.
2. **No IDF weighting.** Generic verbs ("send", "create", "message") match
   hundreds of pieces at +1 each; pieces with more actions have more text
   surface and accumulate more hits regardless of relevance.
3. **Alphabetical tie-breaks + top-12 cut.** Flat integer scores tie
   constantly, so the effective selection was often "the 12 alphabetically
   earliest pieces sharing a generic word with the prompt".
4. **Unrecoverable misses.** The reduce prompt says "No other types exist" —
   if the right piece missed the top 12, the strongest model in the stack
   could not ask for it.

Measured on the new golden set (22 prompts, 43 any-of expectation groups):
**recall@12 = 67%**, with misses like *"text me the weather"* selecting
`cyberark` and `deepl` but no SMS piece, and *"whatsapp confirmation"* —
service named verbatim — flooded out of the top-12 by `google-*` pieces.

### A second, independent bug

`mapPhase` collected up to 8 node ids per cluster, then did
`sort.Strings(selected); selected = selected[:32]`. When more than 32 nodes
were selected, **the cut was alphabetical, not by relevance** — every id late
in the alphabet (`pieces.zendesk.*`, `tool.*`) was silently dropped no matter
what the map models judged. All upstream relevance signal was discarded at the
last step.

### The insight that shaped the fix

The old code assumed "the piece universe is far too large to hand a model
whole". Measured against the real index, that is true at the **node** level
and false at the **piece** level:

- 707 pieces × every action label, fully untruncated ≈ **144 KB ≈ 35k tokens**
  — comfortably one cheap-model call.
- The average piece has only **9.6 actions**, so most directory entries are
  *lossless* (every action name literally present).
- 62 pieces have >20 actions, and those giants hold **2,573 of 6,758 actions
  (38%)** — which is why *truncating* entries was rejected: it would hide over
  a third of the catalog's capabilities. List everything instead.
- "Custom API Call" appears in **455 of 707 pieces** — pure boilerplate,
  stated once in the directory header and stripped from every entry.

## 2. The new architecture: ROUTE → MAP → REDUCE

```
                                 user prompt
                                      │
        ┌─────────────────────────────┼───────────────────────────────┐
        │ (concurrent)                │                               │
        ▼                             ▼                               │
  MAP: hand-written           ROUTE (pieces only)                     │
  clusters (~12), one   ┌───────────────────────────────┐             │
  small-model call      │ 1. embedding prefilter        │             │
  each, immediately     │    (piecesembed.go, OPTIONAL) │             │
        │               │    prompt vector · 6.7k node  │             │
        │               │    vectors → top-100 pieces   │             │
        │               │ 2. router LLM call            │             │
        │               │    (piecesrouter.go)          │             │
        │               │    full/filtered directory →  │             │
        │               │    ≤12 piece slugs            │             │
        │               │ fallback on ANY failure:      │             │
        │               │    lexical topPieceClusters   │             │
        │               └──────────────┬────────────────┘             │
        │                              ▼                              │
        │               MAP: routed piece clusters (≤12),             │
        │               one small-model call each                     │
        └──────────────┬───────────────┘                              │
                       ▼                                              │
          capFairly: round-robin cap to 32 ids                        │
          (fair cut, deterministic order)                             │
                       ▼                                              ▼
          REDUCE: strong model authors the DAG from selected schemas +
          builtins → validate → repair (×2) → deterministic fallback
```

Everything in the diagram degrades independently and silently — the compiler
never fails to produce a workflow (same discipline the platform already had).

### 2.1 The piece directory (`piecesrouter.go: pieceDirectory`)

One entry per piece, rendered from the merged catalog:

```
google-sheets — Google Sheets [PRODUCTIVITY]: Add Row; Update Row; …full list… | triggers: New Row Added; …
```

Design decisions:
- **Untruncated.** Every action and trigger label of every piece. The token
  math (35k) makes truncation unnecessary, and the 38%-in-giants number makes
  it harmful.
- Triggers listed separately and marked (`| triggers: …`) — "when a customer
  pays" must route to Stripe's *triggers*, not just its actions.
- `Custom API Call` deduped into a single header sentence.
- Real display names + framework categories now flow from the index
  (`piecesindex.go` parses `pieceDisplayName` / `categories`; previously the
  label was mechanically derived from the slug).

### 2.2 The router call (`piecesrouter.go: routePieceClusters`)

- One `planLLMWith` call on the map-model tier (Gemini flash / haiku class),
  20s timeout, returning `{"pieces": ["slug", ...]}`, ≤ `maxPieceClusterCalls`
  (12).
- Prompted to include *every plausibly relevant* piece (a later stage narrows
  precisely) but never pad — recall here, precision in the map phase.
- Returned slugs are validated against **what the model was shown** (not the
  whole catalog); an answer with zero valid slugs is distrusted entirely.
- `ok=false` on any failure (no key, timeout, junk) → caller falls back to the
  lexical prescreen, which was kept verbatim for exactly this role.
- Runs **concurrently** with the hand-written cluster map calls, so the extra
  stage costs ~zero wall clock: hand-written goroutines launch first, the
  router resolves while they're in flight, then the routed piece clusters get
  their map calls.

### 2.3 The embedding prefilter (`piecesembed.go`) — Stage 2, optional

Purpose: (a) shrink the router prompt from 35k → ~5k tokens, (b) survive
future catalog growth, (c) action-level recall — every node has its own
vector, so "generate an image" finds `pieces.openai.generate-image` even
though the piece is named "OpenAI".

**Offline half** — `apps/pieces-worker/src/gen-embeddings.ts`
(`npm run gen:embeddings`, after `gen:index`):
- Embeds each of the 6,758 index nodes as
  `"<pieceDisplayName> — <label>. <description>. <search terms>"` with Gemini
  `batchEmbedContents` (100/batch), `taskType: RETRIEVAL_DOCUMENT`,
  `outputDimensionality: 768`, then **unit-normalizes** (Gemini vectors below
  3072 dims are not pre-normalized; normalized vectors make dot product ==
  cosine).
- Writes two sidecar files next to the index:
  - `embeddings.json` — manifest `{version, model, dims, generatedAt, ids[],
    hashes{id→sha256-prefix}}`; `ids` order defines `.bin` row order.
  - `embeddings.bin` — little-endian float32, `len(ids) × dims` (~20 MB).
- **Incremental**: rows whose `(model|dims|text)` hash matches the previous
  manifest are reused with no API call.
- **Resumable**: on fatal error (quota, network) the vectors embedded so far
  are staged to `embeddings.partial.{json,bin}` (gitignored; the Go loader
  never reads them) and the next run resumes from staging. 429s and fetch
  failures retry with exponential backoff (~2 min total — rides out
  per-minute quota windows).

**Online half** — Go planner:
- `loadPieceEmbeddings` (sync.Once) loads the sidecar; any inconsistency
  (missing file, size mismatch) → nil → prefilter unavailable.
- At plan time: one `embedContent` call for the prompt
  (`taskType: RETRIEVAL_QUERY`, manifest's model/dims, normalized), then a
  brute-force dot product over all vectors **in memory** — ~5M multiply-adds,
  a few milliseconds, no vector database (that class of infra starts mattering
  at millions of rows, not 6.7k).
- **Piece score = its best-matching single node (max roll-up).** Sum was
  explicitly rejected: it would recreate the "big pieces win because they have
  more text" bias that poisoned the lexical scorer.
- Top `routerPrefilterTop` (100) pieces' directory entries go to the router,
  in relevance order. Generous on purpose — the prefilter exists for recall,
  the router for precision.
- Unavailable for any reason → router reads the full directory. The sidecar is
  **never load-bearing**.

### 2.4 The cap fix (`planner.go: capFairly`)

Map results are now collected per cluster (each model's output order = its
ranking). To trim to `totalCap` (32): clusters take alphabetical round-robin
turns contributing their **next-best** id until the cap; only then are the
survivors sorted for a reproducible reduce prompt. The **cut** is fair; the
**order** is cosmetic. (Old behavior: global alphabetical sort, then truncate
— relevance discarded.)

### 2.5 What did NOT change

The reduce phase, validate→repair loop, deterministic fallback graph,
`planCache`, layout pass, engine auto-routing, and the per-cluster map-call
mechanics are untouched. The map-reduce *skeleton* was correct; only the
selection front-end was replaced.

## 3. Evidence — the eval harness

`apps/api/cmd/planeval` (`go run ./cmd/planeval [-pause 20s] [-retries 2] [-v]`):
- 22 realistic prompts, many deliberately *not* naming services ("text me",
  "update the CRM", "back up email attachments to cloud storage").
- Expectations are **any-of groups** — "text me" is satisfied by twilio OR
  clicksend OR any SMS piece; a workflow only needs one. Recall@12 =
  satisfied groups / total groups (43).
- Compares three strategies via `services.PieceSelectionMethods`: `lexical`
  (always), `embeddings` (sidecar + Gemini key), `router` (LLM key). Partial
  coverage is flagged (`[only N/22 prompts answered — treat with suspicion]`).
- This is an eval, not CI — it costs LLM calls and moves with models.

**Results from this session:**
- lexical: **29/43 groups (67%)** — misses catalogued in the PR body.
- router: **7/7 groups (100%)** on the 3 prompts it answered before the
  Gemini free-tier **daily** quota died (confirmed `PerDayPerProjectPerModel`
  429; the OpenAI key was also out of credits). Directionally strong,
  statistically thin — rerun on fresh quota for the real number.
- embeddings: not yet runnable — sidecar generation is quota-limited on the
  current key; **900/6,758 vectors staged**, resumes on re-run.

## 5. Session flow (how this came to be)

1. **Diagnosis.** Read `planner.go`/`piecesindex.go`; identified the lexical
   prescreen's four failure modes *and* the independent alphabetical-truncate
   bug at `totalCap`.
2. **Measurement before design.** Ran the real index through quick analysis:
   707 pieces / 6,758 nodes; full directory ≈ 35k tokens; avg 9.6
   actions/piece; 62 giants holding 38% of all actions; `Custom API Call` in
   455 pieces. These numbers drove every design decision — one-call routing is
   feasible, truncation is harmful, dedupe is worth a header line.
3. **Design discussion** (three iterations with the user): Stage 1 = router
   over a directory; challenge "can one line hold a piece's actions?" →
   answer: make the line BE the action list (lossless for ~95% of pieces);
   challenge "giants?" → answer: drop the one-line constraint entirely, list
   everything. Stage 2 = embedding prefilter for scale + action-level recall.
   (A possible Stage 3 — giving the reduce model a catalog-search tool so it
   can recover from residual misses — was deliberately deferred.)
4. **Implementation** in this order: index metadata parsing → router →
   prefilter → mapPhase wiring + `capFairly` → generator → tests → eval
   harness → docs.
5. **Verification.** All new tests pass; full `go build`/`go vet` clean.
   (`TestLaunchThenCancel` / `TestEmittedEventsBuffered` fail — verified
   identical at `main` via a throwaway worktree: pre-existing, unrelated.)
6. **Quota battles.** Real embedding generation hit free-tier per-minute AND
   daily caps; this *drove a design improvement*: the generator gained
   resumable `partial.*` staging and network-error retries, so constrained
   keys converge across runs instead of starting over. 900/6,758 vectors
   staged. The eval's router leg was likewise quota-starved (3/22 prompts
   answered, all correct); OpenAI fallback key was out of credits.
7. **Ship.** Branch `v1-13`, single commit, PR #24 (no AI attribution, per
   request).

## 7. Operations cheat-sheet

```bash
# regenerate the piece index (after adding/upgrading pieces)
cd apps/pieces-worker && npm run build && npm run gen:index

# generate/resume the embedding sidecar (incremental; safe to re-run any time)
npm run gen:embeddings          # needs GEMINI_API_KEY; resumes from embeddings.partial.*

# measure selection recall
cd apps/api && go run ./cmd/planeval -pause 20s -retries 2 -v

# unit tests for the new pieces
go test ./internal/services/ -run 'TestPieceDirectory|TestRoutePiece|TestCapFairly|TestLoadPieceEmbeddings|TestRankPiece'
```

Degradation ladder (nothing here can break workflow creation):
sidecar missing → router reads full directory → router fails → lexical
prescreen → map calls fail → empty selection → reduce works from builtins →
reduce fails → deterministic fallback graph.
